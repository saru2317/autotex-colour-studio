AUTOTEX / DEPLOYMENT PACKAGE

Install your colour studio
on PHP / cPanel.

This package contains the ready-built webpage, password-protected administrator, STEP converter and 20 reference shades. No Node.js, Composer, database, Cloudflare account or ChatGPT login is required on your hosting server.

Tested on PHP 8.3.33 · Minimum PHP 8.2 · PHP 8.3 or newer recommended · HTTPS required for administration

Keep the private folder outside public_html. Upload and extract the ZIP in your cPanel Home directory, rather than inside the public website folder. The deployment ZIP contains a private, one-time setup key.

1. Prepare cPanel

  1. Open MultiPHP Manager or your host's PHP selector and select a supported PHP version (8.3 or newer recommended) for your website.
  2. Enable SSL/HTTPS for the domain through SSL/TLS Status / AutoSSL, if it is not already enabled.
  3. Open File Manager. Under Settings, enable Show Hidden Files so that the supplied .htaccess and .user.ini files are copied too.

2. Place the two folders

Upload/extract the package in cPanel Home. Then place its folders as follows. Replace YOUR_CPANEL_USER with your account name.

/home/YOUR_CPANEL_USER/
├── autotex-private/              ← package's autotex-private folder
│   ├── bootstrap.php
│   ├── default-catalog.json
│   ├── setup-key.txt             ← private, one-time setup key
│   └── .htaccess
└── public_html/
    └── colour-studio/            ← package's public_html/colour-studio contents
        ├── index.php
        ├── admin.php
        ├── setup.php
        ├── api.php
        ├── logout.php
        ├── paths.php
        ├── assets/
        ├── cad/
        ├── .htaccess
        └── .user.ini

Create a new colour-studio folder within the existing public_html. Copy the package's public_html/colour-studio contents into it; do not replace your existing website's public_html folder.

For the layout above, no path editing is needed. For an addon domain, custom document root or root-level installation, edit the $privatePath assignment in the public paths.php to the full location of your private folder, for example:

$privatePath = '/home/YOUR_CPANEL_USER/autotex-private';

The PHP process needs owner write access to autotex-private. It automatically creates its data and session folders. Keep those private; do not use 777 permissions. On normal cPanel hosting, files should be owned by your cPanel account.

3. Confirm PHP upload limits

The included .user.ini requests the following settings. In MultiPHP INI Editor, confirm these limits are allowed by your host. Changes may take a few minutes to take effect.

SettingValue
upload_max_filesize24M
post_max_size48M
memory_limit128M or more
max_execution_time120
max_input_time120

The application allows a STEP file up to 20 MB and its converted GLB preview up to 20 MB. Both travel in one upload, which is why the POST allowance is larger. Conversion occurs in the browser and limits model detail to one million vertices.

4. Create your administrator

  1. Open https://YOUR-DOMAIN/colour-studio/setup.php.
  2. In cPanel File Manager, view /home/YOUR_CPANEL_USER/autotex-private/setup-key.txt. Paste its contents into the Private setup key field.
  3. Choose an admin username and a unique password or passphrase of 14–72 bytes. No default username or password is supplied.
  4. Select Create administrator. The one-time setup key is deleted automatically and initial setup becomes unavailable.

Future administrator sign-in: https://YOUR-DOMAIN/colour-studio/admin.php. Visitors use https://YOUR-DOMAIN/colour-studio/.

5. Add your product

  1. In Admin, enter the product name and choose an .stp or .step file.
  2. Select Convert & prepare product and review the 3D preview.
  3. Enable the colours you want visitors to see. Names, codes and HEX values remain editable.
  4. Select Save changes. Open or reload the public studio to see the saved model and colours.

The package starts with the illustrative bobbin and all 20 reference colours. It does not include any product uploaded to the hosted preview. Upload your product after installation. Unsaved uploads do not replace the active product.

Administration and backups

Passwords are hashed on the server. Admin sessions use HTTP-only, same-site cookies and expire after 30 minutes without activity, with an eight-hour maximum. Login attempts are rate-limited; state-changing operations require a session security token. Public visitors can retrieve the visible 3D mesh, but the original STEP source remains administrator-only.

Back up the entire autotex-private folder, particularly admin.json and data/. Keep setup keys, backups and this ZIP outside public_html. Allow disk space for both source and preview files, up to approximately 40 MB per uploaded model.

Password recovery: through cPanel File Manager, rename private admin.json to a backup name and create a new private setup-key.txt containing at least 40 random characters from a password manager. Visit setup.php to create the replacement account. Existing product and colour data remain in place. Remove the old account backup after successful recovery.

Troubleshooting

  • Private files not found: check the folder layout and the $privatePath in paths.php.
  • Private folder inside the document root: move it outside the domain's public document root. The application intentionally refuses this unsafe layout.
  • HTTPS required: use the https:// URL. If your host terminates TLS through a proxy, ask it to set the PHP HTTPS environment correctly; the application does not trust arbitrary forwarded headers.
  • Upload missing / too large: check both PHP limits and any server, firewall or proxy body-size limit. In some cPanel configurations, .user.ini changes must be made through MultiPHP INI Editor.
  • Storage or session error: check owner write permissions and PHP's open_basedir restrictions. Ask the host to permit the private path; do not move confidential files into the public website folder.
  • HTTP 500 before the application loads: inspect cPanel Errors / the PHP error log. Some hosts restrict Options -Indexes in .htaccess; ask the host to allow the directive or remove only that line if necessary.
  • 3D preview unavailable: use a browser with WebGL and WebAssembly enabled. The static cad/ folder and its WASM file must be uploaded completely.
  • Settings changed in another session: reload Admin before editing again to avoid overwriting someone else's saved changes.

Developer source and colour references

frontend-source/ is included for future design changes. It is not needed on the hosting server. A developer can run npm install and npm run build in that folder. Replace the public assets/ and cad/ directories with the build results, rename built index.html to public shell.html, and copy dist/.vite/manifest.json to public asset-manifest.json. Keep the PHP files.

The RAL web swatches and dealer-published Pantone Coated values are documented in COLOUR-REFERENCES.json. Pantone C is provisional until your supplier confirms the finish. Digital colours and lit 3D renders are screen references; use physical samples for final approval.

Third-party notices and upstream source links are supplied in THIRD-PARTY-NOTICES.txt and licenses/.
